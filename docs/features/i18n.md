# Languages (Amharic and English)

Frontend: `frontend/src/i18n.js`, `frontend/src/locales/{en,am}.js`, `frontend/src/components/LanguageSwitcher.vue`, `frontend/src/utils/dateLocale.js`.
Backend: `PUT /api/users/me/language` ([user-controller](user-controller.md)), `users.language` (`db/sql/015.add-user-language.sql`).

## What a user sees

The UI ships in **Amharic** (`am`) and **English** (`en`). Amharic is the default; English is the fallback for any string the Amharic catalogue has not translated yet, so a half-finished translation degrades to English rather than to a raw key.

The switcher sits in three places, and every one of them behaves the same:

| Where | Who sees it |
|-------|-------------|
| The sign-in page, under the card | everyone |
| The rail's account block (from `lg`) | signed-in staff |
| The top bar (below `lg`) | signed-in members |
| The Profile page, in its own card | everyone signed in |

Choosing a language applies **immediately** and is then saved in two places: `localStorage['locale']` for this device, and the account's `language` column when someone is signed in. The account wins on the next sign-in, so the choice follows the person to another device; signing out leaves the device preference alone.

## Rules

- **A sentence is never assembled from translated fragments** where another language would order the words differently. Counts and lists go through `vue-i18n` interpolation (`{n}`, `{range}`) and the `|` plural forms; the conjunction between list items is itself a catalogue entry (`common.listSeparator`, `dues.listAnd`).
- **`src/utils/` keeps values, tones and CSS classes; `src/locales/` keeps every word.** A function that produces a sentence takes the `t` of `useI18n()` as its last argument (`owedSummary(cells, t)`, `duesBadge(member, paidByMember, currentMonth, t)`, `activityTypeKey(type)` returns a key rather than a word). Where a module runs outside a component — the router guard, the auth store, the Axios interceptor — it uses `i18n.global.t`.
- **Dates follow the language, the calendar does not.** `formatDate` (`utils/index.js`) picks a date-fns locale from the current language, so month and weekday names are Amharic while the Gregorian calendar and Latin digits stay as they are. Money stays `en-US`/USD.
- **`<html lang>`** is set at load from `index.html` and kept in step by `setLocale`.
- The Ethiopic script is already covered: `@fontsource/noto-sans-ethiopic` is imported in `main.js` and `--font-sans` lists it after IBM Plex Sans.

## The Amharic catalogue is machine-drafted

`frontend/src/locales/am.js` carries a header saying so: **the strings were produced by Claude and have not been checked by a native speaker.** Church vocabulary (dues, household, member statuses) is the most likely place to be wrong. Review it before this language is used with a real congregation.

## Adding a string

1. Add the key to `frontend/src/locales/en.js` **and** `am.js`, in the same order in both files — a reviewer reads them side by side.
2. Use it as `$t('namespace.key')` in a template, or `t('namespace.key')` from `useI18n()` in a script.
3. Nothing else: no build step, no extraction tool. `en` is the fallback, so a missing `am` key shows the English one.

## Adding a language

1. Copy `locales/en.js` to the new locale file, translate it, and register it in `i18n.js` (`messages` and `SUPPORTED_LOCALES`).
2. Add the language's own name to `common.languages` in **every** catalogue — the switcher names each language in its own words.
3. If date-fns ships that locale, use it in `utils/index.js`; if it does not (it has no `am`), build one beside `utils/dateLocale.js` from ICU's names.
4. Widen the backend: `User.isSupportedLanguage` and the `@Pattern` on `UpdateUserLanguageRequest`.

## Known issues

- **The activity log's per-entry text is English.** `ActivityLog.description` (for example "Signed in") is written by the backend; only the type badge beside it is translated. Translating it needs the Java side to render per request, which this pass did not do.
- **The same applies to server validation errors and emails.** Only the frontend catalogue is translated; a field error that comes back from the API is in English.
- **`docs/features/*-view.md` quote the old hard-coded English strings** where a screen's copy is listed. Those lists are now out of date.
